Project Σ API

API version 1 · OpenAPI 3.0.3 · live spec at /api/openapi.json

DB-native character library server. Clients do zero heavy lifting: querying, filtering, sorting, and windowing all happen server-side. All timestamps are unix milliseconds. Every collection GET says what it answers in its x-collection: a page ({items, total, limit, nextCursor}: 100 rows unless limit asks, at most 1000 unless the operation names its own numbers, a limit outside them refused by name; a reader that needs the whole set walks nextCursor with after, and count=false skips the total), the whole set as a plain array or document with what bounds it. info.version is the API's own version (apiVersion on /api/health): it moves only when a route is removed or a shape a client reads changes. From the first public release on, an operation marked deprecated here leaves in a later release, and a form a list still answers until a later API version is named in its x-collection deprecated, with that version in until. Multi-user mode (server.yaml multiUser: true) gates every user surface behind an HttpOnly SameSite=Strict session cookie from /api/auth/login; single-user mode needs no auth and everything resolves to the default user. A 401 that means "sign in" carries X-CL-Auth: required. A 401 without it is no request to sign in: a refused login or password change under /api/auth, or a site's refusal a provider route passes through (a wrong password at a site's login, an expired site token). A request may send X-UTC-Offset, the reader's clock in minutes east of UTC, and X-Time-Zone, its IANA zone (Europe/Paris): the time macros a prompt or a sent message holds ({{time}}, {{date}}) answer in the offset, and a stored date written without a zone (a message's createdAt, {{idle_duration}}) is read in the zone, else at the offset, else in the server's own.

The name is read as the duplicate check reads it (version and edit suffixes and edge decoration stripped, compatibility-folded, lowercased, the part before a || as a name of its own) and matched against the exact name, names starting with it as a word (a space, dash, pipe, colon, comma or period after it) and names that are a word of it, the same over the page names provider links carry (answered with the page name as the row name); each row graded exact or prefix, a row the rule does not relate left out, a name under three characters relating to nothing. GET /api/characters/duplicates The duplicate scan over the library, on the server: every pair whose names relate (exactly, as a word of the other, or within a few letters) or whose description and first message are one text under two names, scored on both full cards. A pair by two different authors whose texts are far apart is never scored: a shared name alone is no duplicate. Two cards linked to different listings on one site are weighed by their own text (description or first message: at 0.6 word overlap the same card, under 0.3 another), else their creator notes (0.4 and 0.3); another card is never listed, one the text cannot place is listed with that reason. Characters linked to one provider path group at 100. Answers groups of ids with their scores, never the characters; a client reads the members it shows by id. One scan per library at a time, a second request joins it
CollectionThe whole set: a scan: groups of ids and scores, never rows.
Responses
200 object groups best first: by confidence, then by the best score in the group
